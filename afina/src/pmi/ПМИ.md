# ПРОГРАММА И МЕТОДИКА ИСПЫТАНИЙ (ПМИ)
## СПО «Афина NextGen» · редакция 1.0 (этап G1–G2, эталонная CPU-реализация)

### 1. Объект испытаний
Ядро ENG6+, ГИС-ядро, сервер API (аутентификация/RBAC/аудит/очередь), ИИ-слой (RAG),
каталог КСИМ-ДД и ОШС, веб-клиент (включая WebGL-конвейер).

### 3. Методика
1. Испытания выполняются на эталонных наборах (Приложение Е) в фиксированной среде.
2. Каждое испытание: предусловие → действие → ожидаемый результат → фактический → вердикт.
3. Результаты фиксируются генераторами протоколов (машиночитаемо + md).
4. Отрицательные тесты обязательны (INT-001): некорректные вход отклоняется с объяснением.
5. «Реализовано» ≠ «принято»: вердикт PASS проставляется только при совпадении с критерием ТЗ.

### 4. Средства измерений
Эталонные значения MAT-01 — аналитические формулы (FSPL 32.44+20lg f+20lg d и др.);
внешние СИ не требуются (программный объект). Для MIL-05 (аппаратные испытания изделий) —
реестр СИ в модуле «Испытания» (поверки контролируются, TST-002).

### 5. Порядок проведения и критерии закрытия замечаний
По ТЗ §13.5: критический блокирует приёмку; значительный — приёмку подсистемы;
минорный — при согласованном плане; рекомендация — фиксируется. Статусы замечаний раздельны.

### 6. Ограничения текущей редакции
- Испытания выполняются на эталонной CPU-реализации (Python); целевое ядро C++/Vulkan
  проходит те же эталоны при портировании (допуск MOD-002 фиксируется актом).
- MIL-01…12: программная часть автоматизирована (12/12); аппаратурная часть MIL-05/10 (реальные СИ и изделия) — стенд заказчика.
- AUT-T03/T04 (офлайн-лицензия, автономное обновление/откат установщика) — стенд; AUT-T05/T06/T07 автоматизированы (tools/backup.py, run_132.py режим Б, аудит локальный).
- Нагрузочные S3/S4 на целевом железе — программа готова, выполнение на стенде заказчика (см. план G5).
