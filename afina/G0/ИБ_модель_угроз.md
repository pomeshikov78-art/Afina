# Модель угроз ИБ (проект, к утверждению Заказчиком) — §8.1

## Активы
1. Инженерные данные проектов и базовые линии (целостность — критична).
2. Каталог и расчётные модели (подмена → недостоверные решения).
3. Журнал аудита (неизменяемость — доказательная база).
4. Учётные данные и сессии пользователей.
5. Персональные/агрегированные кадровые данные (минимизация).

## Границы доверия
- Режим А: периметр внутренней ЛВС; сервер↔клиенты; сервер↔СУБД/хранилища.
- Режим Б: граница одного АРМ/замкнутой сети; носители переноса — отдельная доверенная процедура.

## Нарушитель (категории)
- Н1 внешний нарушитель с доступом к сети контура (режим А);
- Н2 внутренний пользователь с легальной учётной записью (превышение полномочий);
- Н3 администратор смежной подсистемы;
- Н4 поставщик/сопровождение (цепочка поставки: подмена пакетов обновления).

## Угрозы и меры (реализовано в эталонной версии G1–G2)
| Угроза | Нарушитель | Мера | Статус в коде |
|---|---|---|---|
| Подбор/кража учётных данных | Н1,Н2 | scrypt-хэширование, HMAC-токены с TTL, блокировка регистрации после bootstrap | реализовано (server/core.py) |
| Превышение полномочий | Н2 | RBAC по матрице Приложения Н на КАЖДОЙ операции сервера; отказы в аудит | реализовано + E2E-тесты |
| Подмена критического решения одним лицом | Н2,Н3 | Maker–Checker (SEC-005): сервер отклоняет само-согласование | реализовано + тесты |
| Фальсификация/удаление журнала | Н2,Н3 | хэш-цепочка аудита, append-only, ротация только регламентом; verify-эндпоинт | реализовано + тесты |
| Подмена пакета обновления/переноса | Н4 | bundle_manifest + проверка при запуске (SEC-002, AUT-T07); подпись на стенде | скрипты готовы, подпись — стенд |
| Утечка закрытых полей при экспорте | Н2 | SEC-004 фильтр экспорта (тест test_04) | реализовано |
| Несанкционированное переключение режима А/Б | Н2,Н3 | AUT-003: режим фиксируется при развёртывании | реализовано (демонстратор+сервер-конфиг) |
| Скрытые внешние обращения | Н1,Н4 | AUT-008: ядро stdlib-only, сетевой монитор; протокол AUT-T02 (0 исходящих) | протокол сформирован |
| Подмена телеметрией базовой линии | Н2 | DGT-002: телеметрия — только наблюдаемое состояние | реализовано + тест |

## Криптография
Состав и класс СКЗИ определяет Заказчик (§8.1/8.2). В коде — интерфейс CryptoProvider
(server/core.py): замена stdlib-реализации на сертифицированный компонент выполняется
без изменения логики. Наличие сертифицированного компонента НЕ означает сертификации Системы.

## Государственная тайна
При обработке сведений, составляющих гостайну, класс защищённости, СКЗИ и аттестация
устанавливаются уполномоченным Заказчиком ДО утверждения архитектуры (§8.2).
