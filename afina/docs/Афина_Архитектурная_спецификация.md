# Архитектурная спецификация (позиция 4 комплекта поставки, §11.1)

## 1. Компоненты и границы
```
┌──────────────────────────── Контур (режим А/Б, внешних обращений нет) ───────────────────────────┐
│  Клиент (src/client/index.html, раздаётся сервером)                                               │
│    └─ REST /api/v1 (JSON) ─ Bearer-токены (HMAC)                                                  │
│  Сервер (afina/server/app.py, stdlib ThreadingHTTPServer)                                         │
│    ├─ RBAC (Прил. Н) на каждой операции · аудит-хэш-цепочка (SEC-003) · идемпотентность (INT-002) │
│    ├─ Очередь расчётов (ARC-003, персистентная queue.json)                                        │
│    ├─ Ядро ENG6+ (eng6/): RF/NET/PWR/THM/REL/OPT/LCC/COSIM/суррогаты + паспорта (MOD-005)         │
│    ├─ ГИС-ядро (gis/): CRS, форматы, MTW, тайлы+манифест, 3D-загрузчики, round-trip               │
│    ├─ Службы жизненного цикла: twin.py (DGT), cfg.py (CFG), ntf.py (NTF), dat.py (DAT)            │
│    ├─ Профили: vt.py (ВТ-01…08), game.py (§4.11)                                                  │
│    ├─ ИИ-слой (ai/): RAG + explain (AI-001/002), отключаемость (AI-003); точка расширения — LLM   │
│    └─ Хранилище (server/core.py): SQLite ⇄ идентичная логическая схема PostgreSQL+PostGIS         │
└────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 2. Потоки данных
- Расчётный: клиент → /calc (постановка) → очередь → обработчик (ENG6+) → паспорт → calcs → клиент (опрос). Тяжёлые расчёты не блокируют интерфейс (ARC-003).
- Данные объектов: создание/блокировки (совместные сессии) → валидация (DAT-002) → конфликты → арбитраж (DAT-004) → базовые линии → архив воспроизводимости (DAT-006).
- Двойник: телеметрия → наблюдаемое состояние (базовая линия НЕ изменяется, DGT-002) → сценарии (оценка) → независимая валидация → DT-5.
- ИБ: все операции → аудит (хэш-цепочка) → verify; экспорт → SEC-004 фильтр.

## 3. Границы безопасности
- Периметр: единственный HTTP-слушатель на loopback/внутри контура; исходящие соединения отсутствуют by design (AUT-002/008; подтверждено AUT-T02, §13.2 режим Б).
- Аутентификация/сессии: scrypt (n=16384), HMAC-токены, TTL 8 ч. Точка подключения СКЗИ — CryptoProvider.
- Разделение полномочий: RBAC (9 ролей), Maker–Checker на утверждениях (SEC-005), роли верификации отделены от ролей исполнения.
- Данные: персональные/закрытые атрибуты исключаются при экспорте (SEC-004); подменный перенос отклоняется по sha256 (AUT-T07).

## 4. Целевой стек (§3.3) и абстракции
Эталонная реализация — Python 3.11 stdlib (подтверждена протоколами). Целевые: сервер Go (контракт /api/v1 сохранён), ядро C++/Vulkan (ARC-002: backend-поле паспорта фиксирует среду; регрессия по эталонам MOD-002/004 обязательна), PostgreSQL+PostGIS (схема готова), MinIO/RabbitMQ — после проверки лицензий (реестр лицензий G0, путь A/B).

## 5. Расширение
Новая расчётная функция = обработчик в очереди + запись в реестр моделей (§4.5.9) + эталон MAT. Новое правило = данные в реестре правил (CFG-004), не код. Новая модель ИИ = подключаемый компонент ai/ при сохранении запретов §4.10.2.
