# План сопровождения, исправления дефектов и развития (позиция 15, §11.1)

## 1. Уровни поддержки
- L1 (эксплуатация): мониторинг healthz/очередь/панель ВТ-08, резервное копирование по регламенту, типовые неисправности (Руководство сопровождения §5).
- L2 (инженерный): дефекты, расхождения расчётов с эталонами, миграции данных; вход — зарегистрированное замечание в Системе (жизненный цикл §4.8.6).
- L3 (разработка): изменения ядра через CR-цикл (§4.8.2) с Maker–Checker и регрессионным набором.

## 2. Регламент исправления дефектов
Критический → исправление вне очереди, повторный тест обязателен (§13.5); значительный → блокирует приёмку подсистемы; минорный → по согласованному плану; рекомендация → фиксируется в реестре. Каждый дефект: замечание в Системе → CR → исправление → регрессия (145 тестов + протоколы) → закрытие с основанием.

## 3. Развитие (очередь после поставки)
1) порт ядра C++/Vulkan с регрессией эталонов; 2) PostgreSQL/PostGIS в проде; 3) SXF/DB3D-адаптеры по лицензиям; 4) локальная LLM (опция); 5) полный 3D SBR/UTD; 6) браузерный Push; 7) расширение реестра суррогатов (GP/RBF).

## 4. Версионирование
Релизная линия — git-теги (g0-docs … g5-*); журнал — CHANGELOG.md и releases/VERSIONS.md. Обновление не переписывает утверждённые результаты (CFG-004); совместимость API /api/v1 фиксируется спецификацией.
