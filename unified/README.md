# ЕДИНАЯ ПРОГРАММА «АФИНА» — совмещение двух линий в один продукт

**Основание:** план совмещения из разбора репозитория от 26.10.2026 (`Afina_РАЗБОР_2026-10-26.md`, раздел 6) ·
**Ветка:** `unified-platform` · **Принцип:** «Афина» — платформа и единая точка входа, ENG6-PLAN — вычислительный контур.

Единая программа соединяет две независимые линии репозитория **без переписывания ядер**
(ADR-001 линии B: вендор ENG6 — единственный источник истины по математике;
линия A остаётся верификатором и fallback режима Б):

| | Линия A · `../afina/` | Линия B · `../eng6-service/` | Роль в единой программе |
|---|---|---|---|
| Платформа | СПО «Афина NextGen» (Python 3.11 stdlib-only): ГИС, каталог 1940–2036, ОШС, ЦД, RBAC, аудит-хэш-цепочка, ИИ-RAG, ВТ, геймификация, клиент WebGL | — | Единая точка входа, данные, роли, аудит, паспорта |
| Математика | ENG6+ (10 моделей: RF-01…09, NET/PWR/THM/REL/OPT/LCC) | **ENG6 v5.1.0** (вендор, 151 модель MLIB, sha256 `adb610c9…`) + планировщик MILP (11 фаз) | Канон расчёта — ENG6-JS; Python — независимый верификатор (ARC-002) и fallback |
| Сервис | REST :8470 (scrypt+HMAC, RBAC, очередь) | REST :8080 (4 рубежа backpressure, Prometheus, аудит NDJSON) | Sidecar-архитектура: platform → engine |

## Быстрый старт

```bash
# 1. Стек целиком (без Docker; нужны node ≥ 20.11 и python ≥ 3.11)
./scripts/start_stack.sh          # engine :8080 + platform :8470 → unified/var/stack.env
./scripts/stop_stack.sh

# 2. Или Docker-стек (после обкатки на стенде)
docker compose -f deploy/docker-compose.unified.yml up -d --build
#    platform → http://localhost:8470 · engine → :8080 · grafana → :3000 · prometheus → :9090

# 3. Проверки единой программы (всё stdlib/zero-deps)
cd bridge && python3 -m unittest discover -s tests -p "test_*.py"   # 37/37 (live-тесты сами поднимают контур)
python3 xverify.py                                                   # XVER 117 точек → protocols/
cd ../scripts && python3 demo_e2e.py                                 # E2E 7 шагов → protocols/
cd ../rtm && python3 build_unified_rtm.py                            # RTM 175 → rtm/artifacts/

# 4. Единое рабочее место (PoC): unified/ui/workspace.html при поднятом стеке
#    (фрейм платформы :8470 + прямые запросы к контуру :8080 по CORS)
```

## Политика честности (наследие обеих линий — обязательна для единой программы)

1. Расхождение выше допуска — **измеренная величина протокола**, а не повод подогнать тест (стадия RAW сохраняется вместе с ALIGNED).
2. Семантические несовместимости не маскируются: `hata(suburban)` вендора ≠ Python-поправка — исключение с обоснованием в протоколе и рекомендация для планирования.
3. Вендор ENG6 **не изменяется** (§9.3.1 Дополнения №2); все согласования — на стороне платформы (cm_db=3.0, деление на √1000 для fresnelR).
4. Статус требования в RTM без протокола/теста — «не подтверждено», даже если реализация существует.
5. Координаты не логируются; аудит каждого запуска (X-Requestor + sha256 входа).

## Юридическая оговорка

Ядро ENG6 v5.1.0 извлечено из изделия «Планировщик связи» E6/8.0; `eng6-service/package.json`
содержит `license: UNLICENSED`. **До решения правообладателя (IP-аудит, шаг 1 WORKPLAN) единая
программа поставляется только внутри контура заказчика и не публикуется.** Публикация ветки
в открытом репозитории — на усмотрение владельца после закрытия шага 1.
